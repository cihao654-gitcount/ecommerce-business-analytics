## 3. 非数字开头的商品编码处理建议

处理方式含义：

- **保留**：描述支持其为具体商品，继续留在候选范围，不等于核实了每笔交易真实性。
- **排除出正常商品销售**：建议不进入本项目商品销量与商品购买次数分析，仍保留原始记录并可单独分析。费用、折扣等是否纳入整体经营金额，需另定口径，不能由此直接计算会计收入。
- **待确认**：现有描述不足以判定用途；建议后续主分析暂不纳入，单独统计并披露覆盖影响，不直接删除。

### 分类规模与检查边界

- 保留：143 行。
- 排除出正常商品销售：3702 行。
- 待确认：864 行。
- 本次查询命中合计：4709 行，共 40 个编码与描述组合。这些计数只覆盖非数字开头的编码，不是全体商品分类结果。

编码不以数字开头只是发现候选问题的条件，不能作为批量排除规则。反过来，以数字开头也不保证一定是普通商品。本项目当前分类为有限的规则方案，并非完整商品主数据认证。

当前视图使用已审阅编码的明确名单排除，而非直接排除所有非数字开头的编码。BANK CHARGES 和 ADJUST 各有不同描述，因此证据表分行展示；前后空格未经修改，不据此制造新的业务商品类别。

## 4. 视图实施与核验结果

2026-11-14 已确认数据库 eco_b_analytics 中的 v_sales_transactions 视图创建成功。数据库中的实际定义与已验收筛选逻辑一致，保留原表全部 11 个字段，包括 raw_id、source_sheet、source_row。编码名单中的排除项目与待确认项目分别核算，待确认的 M、S 暂不纳入主分析。

商品购买次数定义为符合分析条件的记录中，每个 stock_code 对应的不同 invoice 数；同一商品同一发票出现多条明细只计一次。商品销量是按最终确定交易口径累计 quantity；不能把明细行数当作销量或购买次数。

当前已完成既定规则下的分析视图，不代表所有交易的业务真实性已核实；同表同值记录、特殊记录用途等限制仍适用。规则排除的行数不能称为真实损失、退款次数或客户流失数量。

### 使用及复现

在已完成原始数据导入的数据库中，先执行 04_cleaning_rules.sql 核对计数，再执行 05_create_sales_view.sql 创建视图。创建脚本使用 CREATE VIEW，适用于该名称尚不存在的环境；同名视图已存在时不应重复执行创建部分，可直接查询，需修改定义时另行审核更新。

视图保存查询逻辑，不是数据快照；原始表变化后，查询结果会随之变化。可用以下只读语句复核：

```sql
select source_sheet, count(*) as total_count
from eco_b_analytics.v_sales_transactions
group by source_sheet;
```

后续商品分析从该视图取数，并按具体问题限定日期。客户分析另行筛选客户编号存在的记录，报告其覆盖范围。
