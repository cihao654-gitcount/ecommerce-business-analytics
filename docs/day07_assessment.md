## 这道题怎么算

在 `v_sales_transactions` 中取 2011 年 11 月的记录（含 11 月 1 日，不含 12 月 1 日），排除客户编号缺失。先问同一客户买同一商品时用了几张不同发票，保留至少两张的组合。得到 4,629 行后，再对客户编号去重，剩 **412 人**。一个人回购三种商品，就会占三行。

| 核验项 | 结果 |
|---|---|
| 满足条件的客户与商品组合 | 4629 个 |
| 涉及的不同可识别客户 | 412 名 |
| 每个满足条件组合的不同发票数 | 最少 2，最多 12 |
| SQL 独立核对 | 先对客户、商品、发票去重，再分组计数，逐组结果一致 |
| pandas 与 SQL 对照 | 组合数 4629、人数 412，一致 |
| notebook 保存的执行顺序 | 六个代码单元依次为 1、2、3、4、5、6 |
| notebook 保存的执行错误 | 0 |

学员报告已重启内核并从头运行；保存的读库输出、连续执行编号和最终结果与之相符。这次验证用的是本机已有环境。412 人只涵盖这个月内至少回购一种商品的可识别客户。

## 运行环境里值得留意的两件事

Notebook 约 25.5 KB，保留了 4,629 和 412 的运行输出。连接使用 `.env` 和 `URL.create`，创建引擎后实际读库才验证了连接。当时检查的文件及暂存版本里没有发现数据库密码或带凭据的 URI，`.env` 已被 Git 忽略。检查范围限于当时版本。Notebook 使用本机绝对路径，换机器要调整。先读整个视图再用 pandas 筛选能得出正确结果，以后可以把选列和日期条件提前到查询中。

还有一次 API 判断需要更正。在当时的 pandas 3.1.1 环境里，`purchase.filter(lambda x: x['purchase_count'] >= 2)` 的现场结果与 `query` 一致。导师此前对 `filter` 的说法过于笼统。最初传入单个判断值的写法有问题，题目本身也要求先对发票去重，再筛至少两次购买。
